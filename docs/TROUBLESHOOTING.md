# Диагностика: «после включения ПК ничего не работает»

Схема: контроллер (Telegram-бот) работает на телефоне в Termux, агент — на ПК. Агент сам
подключается к контроллеру по `http://<CONTROLLER_HOST>:<CONTROLLER_PORT>`. Если связи нет,
бот отвечает, но задачи и скриншоты не работают.

## Быстрая проверка

ПК (PowerShell):

```powershell
powershell -ExecutionPolicy Bypass -File scripts\diagnose.ps1
```

Проверяет ярлык автозапуска, процессы агента, `GET /api/v1/status` контроллера (признак
`agent_connected`) и показывает хвосты логов. Код возврата `0`: агент подключён.

Телефон (Termux):

```bash
~/control-bot.sh status
tail -n 100 ~/controller.log ; cat ~/boot.log
```

Признак «агент работает» один: `agent_connected: true` в ответе `/api/v1/status`. Запущенный
процесс агента этого не доказывает.

## Где логи

| Что | Где |
|---|---|
| Агент (ПК) | `%LOCALAPPDATA%\RemoteControl\logs\agent.log` (ротация, 3 × 2 МБ) |
| Скрипт запуска (ПК) | `%LOCALAPPDATA%\RemoteControl\logs\start_services.log` |
| Контроллер (телефон) | `~/controller.log` (при перезапуске сохраняется в `.1`, если больше 5 МБ) |
| Автозагрузка Termux | `~/boot.log` |

## Как читать лог агента

| Сообщение | Что значит |
|---|---|
| `Подключено к Controller …` | всё хорошо |
| `Нет связи с Controller …` | адрес недоступен: проверьте `CONTROLLER_HOST` на ПК (IP телефона, не `0.0.0.0`), что контроллер запущен и на телефоне `CONTROLLER_HOST=0.0.0.0`, нет изоляции клиентов в Wi-Fi |
| `ответил ошибкой HTTP …` | контроллер отвечает, но с ошибкой: смотрите `controller.log` |
| `отклонил авторизацию` | разный `AGENT_AUTH_SECRET` или часы ПК и телефона расходятся больше чем на 60 с |
| `Неожиданная ошибка …` | с трейсбэком: это ошибка в коде, приложите её к отчёту |
| `связь … восстановлена` | агент переподключился сам |

Повторяющиеся ошибки пишутся не чаще раза в минуту, поэтому лог не раздувается.

## Автозапуск на ПК

```powershell
scripts\install_autostart.ps1            # службы стартуют только после /wake (-RequireWol)
scripts\install_autostart.ps1 -Always    # службы стартуют при каждом входе в Windows
scripts\install_autostart.ps1 -Uninstall
```

* В режиме `-RequireWol` при **ручном** включении ПК службы не стартуют намеренно, если
  контроллер ответил, что `/wake` не запрашивался. Если контроллер не ответил за ~1 минуту, службы
  запускаются: агент сам переподключится.
* Автозагрузка срабатывает **после входа пользователя в Windows**. Если ПК разбудили по сети и он
  остановился на экране входа, настройте автовход.
* На ПК должно быть `CONTROLLER_MODE=distributed`. При `local` режим `auto` запустит на ПК второго
  бота; с тем же токеном два бота будут конфликтовать (`TelegramConflictError`).

## Контроллер на телефоне

Контроллер запускается под supervisor (`scripts/termux/run-controller-loop.sh`): при падении он
перезапускается с паузой 5 → 60 с. PID из файла проверяется по командной строке, чужой процесс
после перезагрузки Android за контроллер не принимается.

После `git pull` скрипты в `~` и `~/.termux/boot` нужно обновить (это копии):

```bash
bash scripts/termux/setup-autostart.sh
~/control-bot.sh restart
```

Если лог обрывается без трейсбэка, Android, скорее всего, убил Termux: отключите оптимизацию
батареи для Termux и Termux:Boot, оставьте Wi-Fi включённым в режиме сна.
