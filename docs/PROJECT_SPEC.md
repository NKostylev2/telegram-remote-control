# Спецификация требований проекта (docs/PROJECT_SPEC.md)

Документ описывает функциональные и нефункциональные требования к системе удалённого управления **Telegram Remote Control**, разграничение функциональности на этап MVP и последующие версии, а также анализ спорных технических решений и компромиссов.

---

## 1. Термины и определения

* **Целевой ПК (Target PC)** — персональный компьютер под управлением Windows, на котором установлен и настроен Antigravity CLI, и на котором выполняются целевые задачи разработки.
* **Контроллер (Controller)** — сервис/узел, принимающий команды от пользователей через Telegram API, управляющий очередью задач и отправляющий сигналы Wake-on-LAN (может быть как внешним устройством, так и локальным процессом в зависимости от архитектурной конфигурации).
* **Windows Agent** — фоновый процесс на Целевом ПК, непосредственно взаимодействующий с операционной системой, запускающий Antigravity CLI, отслеживающий процессы и возвращающий статус.
* **Antigravity CLI (`agy`)** — установленный в системе консольный инструмент агента автоматизации/разработки.
* **Magic Packet (WoL)** — специальный широковещательный сетевой пакет стандарта Wake-on-LAN, содержащий 6 байтов `0xFF` и 16 повторений MAC-адреса целевой сетевой карты.
* **Allowlist (Белый список)** — фиксированный перечень идентификаторов пользователей (`user_id` Telegram) и перечень разрешённых рабочих директорий на диске, выход за пределы которых запрещён.

## 2. Разделение функциональности: MVP vs Будущие улучшения

### 2.1. Объём первого релиза (MVP)

Интерфейс Telegram-бота в MVP строго ограничен следующим набором команд:

| Команда | Назначение | Поведение и критерии |
| :--- | :--- | :--- |
| `/start` | Приветствие и инициализация | Выводит приветственное сообщение авторизованному пользователю с текущим статусом хоста. Неавторизованные пользователи игнорируются. |
| `/help` | Справочная информация | Список доступных команд, описание формата работы и подсказки по синтаксису. |
| `/status` | Мониторинг хоста и задач | Проверка отклика Windows Agent (Online / Offline), текущей активности хоста (Busy / Idle) и информации о выполняемой задаче. |
| `/wake` | Включение ПК (Wake-on-LAN) | Отправка Magic Packet в локальную сеть на MAC-адрес целевой сетевой карты. Отправка пакета не приравнивается к факту включения хоста: бот запускает таймер проверки доступности. |
| `/workspace` | Управление рабочими каталогами | Просмотр списка разрешённых рабочих пространств из `ALLOWED_WORKSPACES` и выбор активного каталога для последующих запусков. |
| `/run` | Запуск задачи Antigravity CLI | Передача промпта для исполнения в выбранном рабочем пространстве. **Обязательное условие**: бот запрашивает явное подтверждение (кнопки «Подтвердить запуск» / «Отмена») перед передачей задачи агенту. После подтверждения задача ставится в очередь SQLite. |
| `/tasks` | Список и история задач | Вывод статуса активной задачи, очереди и последних 10 выполненных задач (`QUEUED`, `RUNNING`, `COMPLETED`, `PARTIAL_SUCCESS`, `FAILED`, `CANCELED`, `INTERRUPTED`). |
| `/cancel` | Отмена задачи | Отмена задачи по ID (`/cancel <id>`) либо активной задачи: немедленная отмена для задач в очереди (`QUEUED`) и безопасное завершение дерева процессов для выполняемой задачи (`RUNNING`). |
| `/result` | Получение результата задачи | Просмотр результата выполнения по ID (`/result <id>`). До 3000 символов возвращается в виде текста, для больших ответов генерируется документ `task_<id>_output.txt`. Строгая авторизация: доступ открыт только инициатору задачи. |

> [!CAUTION]
> **Ограничение MVP:** Выполнение произвольных системных команд (`cmd.exe`, `powershell.exe`) через Telegram **категорически запрещено**. Бот принимает исключительно структурированные запросы к Antigravity CLI в разрешённых рабочих пространствах.

### 2.2. Будущие улучшения (Post-MVP)

* **Интерактивный диалог с Antigravity**: Передача промежуточных ответов пользователя в процессе выполнения задачи (Human-in-the-loop) через Telegram-клавиатуру или ответы цитированием.
* **Управление питанием ОС**: Защищённые команды `/shutdown` и `/reboot` для выключения/перезагрузки Windows-ПК с двухэтапным подтверждением и проверкой отсутствия активных задач.
* **Передача файлов и артефактов**: Возможность выгрузки сгенерированных отчётов, диффов (`git diff`) и файлов изменений напрямую в чат Telegram.
* **Детальный мониторинг ресурсов**: Получение метрик хоста (загрузка CPU, потребление RAM, температура GPU, свободное место на дисках).
* **Расписание и автозапуск**: Запуск задач по расписанию (cron) и автоматическое усыпление ПК при простое более заданного времени.
* **Поддержка нескольких рабочих станций**: Диспетчеризация задач между несколькими ПК через один Controller.

## 3. Детальные функциональные требования (MVP)

### 3.1. Управление доступом и безопасность
1. Система по умолчанию запрещает доступ всем пользователям Telegram, отсутствующим в белом списке `ALLOWED_TELEGRAM_USERS`.
2. Запросы от неизвестных пользователей **игнорируются без ответа** в Telegram (режим скрытности / stealth-режим), чтобы исключить раскрытие назначения сервиса.
3. Внутренний аудит попыток несанкционированного доступа допускается исключительно с фиксацией минимально необходимых обезличенных данных: `user_id` и временная метка (timestamp).
4. Все чувствительные операции (запуск задачи `/run`, прерывание `/cancel`) требуют обязательного интерактивного подтверждения пользователем через Inline-кнопки Telegram до фактического исполнения.

### 3.2. Проверка состояния хоста
1. Контроллер отслеживает доступность Windows Agent через внутренний пинг / опрос heartbeat.
2. Статусы хоста:
   * `Offline` — ПК выключен или сеть недоступна.
   * `Online (Idle)` — агент на связи, система свободна для приёма задач.
   * `Online (Busy)` — выполняется задача Antigravity CLI (указывается `task_id`).
   * `Agent Unreachable` — сетевой узел доступен по пингу, но служба агента не отвечает.

### 3.3. Отправка Wake-on-LAN
1. Команда `/wake` отправляет сетевой Magic Packet (UDP broadcast) на сконфигурированный MAC-адрес и широковещательный адрес подсети.
2. **Разделение событий**: Успешная отправка Magic Packet означает лишь физическую передачу UDP-датаграммы контроллером в сеть. Фактическое пробуждение компьютера зависит от аппаратной части (BIOS/UEFI, сетевая карта, состояние питания) и является отдельным событием.
3. После вызова `/wake` бот переходит в режим ожидания (таймаут 60–120 секунд) и уведомляет пользователя, только когда Windows Agent реально выйдет на связь и подтвердит статус `Online`.

### 3.4. Запуск и контроль задач Antigravity CLI
1. **Привязка к рабочему пространству**: Запуск задачи возможен только в явным образом выбранном рабочем пространстве из `ALLOWED_WORKSPACES` (управление через `/workspace`). Произвольные пути запрещены.
2. **Способ запуска CLI**:
   * Запуск утилиты `agy` выполняется в пакетном неинтерактивном режиме с флагами:
     `agy -p "<prompt>" --output-format json --print-timeout <timeout> --effort <low|medium|high>`
   * Запуск осуществляется напрямую через API подпроцессов Windows (без промежуточного интерпретатора `cmd.exe` / `powershell.exe` и без `shell=True`).
3. **Классификация задач и глубина рассуждений (Reasoning Effort)**:
   * Задачи автоматически анализируются и разделяются на категории (`action`, `query`, `complex`):
     * `action` (запуск оконных приложений, фоновых программ, создание/удаление файлов) — уровень `--effort low` и директива агенту отвечать предельно кратко (1 предложение по факту выполнения) без промежуточных логов и листингов PowerShell.
     * `query` (инспекция процессов, поиск файлов, получение статуса) — уровень `--effort low` с требованием структурированного вывода (таблица/список).
     * `complex` (отладка, поиск ошибок, архитектурный рефакторинг) — уровень `--effort high` с глубоким аналитическим рассуждением.
   * На экране подтверждения задачи отображается распознанный режим и доступна интерактивная кнопка циклического переключения (`low -> medium -> high -> low`) перед фактическим запуском.
4. **Ограничение параллелизма**: В MVP строго допускается выполнение **не более одной задачи единовременно** (Single-task concurrency). При попытке запустить вторую задачу бот сообщает о занятости хоста.
5. **Учётная запись Windows**: Windows Agent обязан функционировать в контексте пользовательской учётной записи Windows (не `LocalSystem`), чтобы иметь доступ к хранилищу учётных данных Windows Credential Manager и пользовательскому профилю Antigravity CLI.

### 3.5. Долговременная очередь, хранение истории в SQLite и получение результатов
1. **Персистентность и схема данных в SQLite (`data/tasks.sqlite3`)**:
   * Все подтверждённые задачи сохраняются в локальной реляционной базе данных SQLite с поддержкой режима WAL (`PRAGMA journal_mode=WAL`) и версионированием схемы (`PRAGMA user_version = 1`).
   * Таблица `tasks` фиксирует:
     * `id`: целочисленный автоинкрементный идентификатор задачи;
     * `confirmation_id`: уникальный строковый ключ операции подтверждения (защита от повторных callback-кликов);
     * `user_id` и `chat_id`: Telegram ID инициатора и чата для уведомлений;
     * `workspace_alias` и `working_directory`: псевдоним и абсолютный путь целевой директории;
     * `prompt`: исходный текст задачи;
     * `effort`: уровень рассуждений (`low`, `medium`, `high`);
     * `status`: жизненный цикл задачи (`QUEUED`, `RUNNING`, `COMPLETED`, `PARTIAL_SUCCESS`, `FAILED`, `CANCELED`, `INTERRUPTED`);
     * Временные метки в формате ISO 8601 (UTC): `created_at`, `confirmed_at`, `queued_at`, `started_at`, `finished_at`, а также `duration_seconds`;
     * `exit_code`, `conversation_id`, `result_text`, `result_file_path`, `error_message`, `warning_message`, `raw_stderr`.
   * Каталог базы данных (`data/`) изолирован от Git в `.gitignore`.
2. **Последовательный фоновый исполнитель (TaskQueue)**:
   * Задачи извлекаются из очереди строго в порядке FIFO с параллелизмом не более 1 (`concurrency <= 1`).
   * Реактивное пробуждение рабочего цикла через `asyncio.Event` при постановке новой задачи исключает холостые циклы ожидания.
   * Уведомления о старте задачи отправляются инициатору в Telegram при переходе в `RUNNING`.
   * При сбое или отмене задачи дерево процессов `AgyClient` на Windows гарантированно завершается, статус переводится в `CANCELED`, а пользователь получает уведомление.
3. **Восстановление после перезапусков (Crash Recovery)**:
   * При старте приложения процедура `recover_on_startup()` проверяет наличие незавершённых задач.
   * Зависшие задачи в статусе `RUNNING` переводятся в статус `INTERRUPTED` с диагностической пометкой («Прервано из-за перезапуска сервиса»). Автоматический повторный перезапуск прерванных задач исключён в целях безопасности.
   * Задачи в статусе `QUEUED` сохраняются в очереди и последовательно берутся в работу после инициализации фонового воркера.
4. **Защита от параллельного запуска нескольких инстансов (SingleInstanceLock)**:
   * Неблокирующая блокировка на системном уровне (`msvcrt.locking` на Windows / `fcntl.flock` на POSIX) для файла `.instance.lock`.
   * Предотвращает одновременный доступ двух процессов к одной базе данных SQLite и конфликты с Telegram Long Polling.
5. **Хранение и доставка результатов**:
   * Если длина вывода задачи превышает 3000 символов, полный вывод сохраняется в защищённом каталоге `data/results/task_<id>_output.txt`.
   * Доступ к `/result <id>` строго ограничен: пользователь может запросить результат только своих собственных задач (`user_id == task.user_id`).
   * Каталог результатов защищён от выхода за пределы (Path Traversal) и имеет ограничение на максимальный размер выгружаемого файла (10 МБ).
6. **Различие между кодом возврата, статусом и фактом исполнения**:
   * *Завершение процесса (Exit Code 0)*: Означает лишь, что CLI завершил работу штатно.
   * *Статус результата (`status`)*: Парсинг JSON-конверта вывода (`SUCCESS`, `PARTIAL_SUCCESS`, `ERROR`, `CANCELED`, `INTERRUPTED`). Статус `SUCCESS` означает, что агент сформировал итоговый ответ без ограничений; статус `PARTIAL_SUCCESS` выставляется при наличии soft-denied инструментов или предупреждений о правах доступа.
   * *Полнота выполнения задачи*: В headless-режиме инструменты, требующие интерактивного подтверждения, по умолчанию мягко отклоняются («soft-denied»), при этом процесс может завершиться с кодом 0, но в `stderr` выводится предупреждение. Агент обязан анализировать как JSON-поле `status`, так и поток `stderr` на предмет отклоненных действий.
7. **Обработка ошибок авторизации**:
   * При истечении сессии или отсутствии токена CLI завершается с ненулевым кодом или ошибкой в JSON-конверте. Бот перехватывает сообщение об ошибке, скрывает внутренние токены и информирует пользователя о необходимости обновить сессию на хосте.
8. **Санитизация секретов**:
   * Все системные секреты, ключи и токены из окружения маскируются функцией санитизации перед выводом в Telegram и записью в логи.

## 4. Спорные функции, альтернативы и компромиссы

### 4.1. Доставка промежуточного прогресса задач
* **Вариант 1 (Частое редактирование сообщения)**: Риск получить HTTP 429 Too Many Requests от Telegram Bot API.
* **Вариант 2 (Дискретные уведомления)**: Сообщение о старте задачи, явный алерт по окончании и возможность запросить текущее состояние через `/status` или `/tasks`.
* *Решение для MVP*: Принят **Вариант 2** как наиболее отказоустойчивый.

### 4.2. Архитектура взаимодействия узлов
* Выбран **Вариант B (Раздельные компоненты)**.
* Во время разработки допускается локальный запуск Контроллера и Агента на целевой машине.
* Для промышленной эксплуатации Wake-on-LAN Контроллер или промежуточный сетевой узел должен быть постоянно доступен при выключенном целевом ПК. Подробно разобрано в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

### 4.3. Режим взаимодействия с Antigravity CLI
* Выбран **пакетный режим с JSON-выводом (`--output-format json`)**. Интерактивный терминал (PTY) для MVP исключён из-за риска неконтролируемой блокировки фонового процесса на Windows.
