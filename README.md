# Telegram Remote Control (Antigravity CLI & Wake-on-LAN)

Проект по разработке системы защищённого удалённого управления компьютером под управлением ОС Windows через Telegram-бота. Основные задачи системы — удалённый запуск ПК с помощью сетевых пакетов **Wake-on-LAN (WoL)**, диспетчеризация и контроль выполнения задач в **Antigravity CLI**, мониторинг доступности хоста и оперативное информирование пользователя.

> [!IMPORTANT]
> **Текущий статус проекта:** Завершён **Этап 5 (Постоянная очередь задач, снимки экрана и UI-улучшения)**.
> Реализована постоянная очередь задач и история выполнения в SQLite (`data/tasks.sqlite3`), фоновый долгоживущий последовательный исполнитель `TaskQueue`, захват снимков экрана `/screenshot`, нативное меню команд Telegram, нижняя панель быстрого доступа, последовательная отправка сообщений-задач из чата, защита от одновременного запуска процессов, сохранение результатов в `data/results/`, команды управления `/tasks`, `/cancel <id>`, `/result <id>` и полный набор из 175 автоматических тестов (`175 passed`).

---

## Цели проекта

1. **Удалённая доступность рабочей станции**: Возможность включить целевой рабочий компьютер под управлением Windows с помощью Wake-on-LAN через постоянно доступный узел, находясь вне дома или локальной сети.
2. **Контроль задач Antigravity CLI**: Инициирование, отслеживание прогресса и получение результатов работы Antigravity CLI (`agy`) в headless-режиме через мобильный интерфейс Telegram.
3. **Безопасность и предсказуемость**: Строгий белый список пользователей (режим скрытности для неизвестных), изоляция рабочих директорий, подтверждение чувствительных операций перед запуском и полный запрет произвольных shell-команд.

## Архитектура и сетевая модель

Система проектируется с разделением ответственности на следующие узлы:

```
[Пользователь Telegram]
          │
          ▼
┌───────────────────────────────┐
│     Telegram Interface /      │  (Long Polling к api.telegram.org,
│     Controller Service        │   валидация прав, подтверждение запуска, WoL)
└──────────────┬────────────────┘
               │ (Постановка в очередь SQLite data/tasks.sqlite3)
               ▼
┌───────────────────────────────┐
│     Sequential TaskQueue /    │  (Фоновый исполнитель очереди,
│     TaskStore (SQLite)        │   одно задание единовременно, сохранение результатов)
└──────────────┬────────────────┘
               │
               ▼
┌───────────────────────────────┐
│         Windows Agent /       │  (AgyClient: безопасный subprocess_exec,
│         AgyClient             │   парсинг JSON, изоляция в white-list каталогах)
└──────────────┬────────────────┘
               │
               ▼
┌───────────────────────────────┐
│       Antigravity CLI         │  (Локальный исполняемый файл agy.exe)
└───────────────────────────────┘
```

* **Сетевая модель Telegram**: Бот использует исходящий механизм **Long Polling** к серверам Telegram (`api.telegram.org`). Для работы **не требуются** публичный статический IP-адрес, проброс портов на роутере (Port Forwarding), регистрация доменов или настройка вебхуков.
* **Режим разработки (local)**: Контроллер, очередь и агент работают в рамках единого процесса на Windows-компьютере.
* **Производственный режим (distributed)**: Контроллер (или WoL-прокси) функционирует на постоянно включённом микрокомпьютере в локальной сети, отправляя WoL Magic Packet при выключенном основном ПК.

## Быстрый старт и запуск

### 1. Требования к окружению
* ОС: Windows 11 (или Linux для Контроллера).
* Python 3.11+.
* Установленный Antigravity CLI (`agy.exe`).

### 2. Установка зависимостей
```powershell
# Клонирование или переход в директорию проекта
cd "M:\dev\Telegram Remote Control"

# Создание и активация виртуального окружения (если ещё не создано)
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# Установка пакета в режиме разработки
pip install -e ".[dev]"
```

### 3. Регистрация Telegram-бота и настройка `.env`
1. Откройте диалог с официальным ботом [@BotFather](https://t.me/BotFather) в Telegram.
2. Отправьте команду `/newbot`, укажите имя и уникальный username бота.
3. Скопируйте полученный HTTP API токен.
4. Узнайте свой числовой `user_id` (например, через бота [@userinfobot](https://t.me/userinfobot)).
5. Создайте файл `.env` на основе шаблона `.env.example`:
```powershell
cp .env.example .env
```
6. Укажите параметры в файле `.env`:
```env
TELEGRAM_BOT_TOKEN=123456789:ABCdefGHIjklMNOpqrsTUVwxyz
ALLOWED_TELEGRAM_USERS=123456789
ALLOWED_WORKSPACES={"backend": "M:\\dev\\my_project", "docs": "M:\\dev\\docs"}
ANTIGRAVITY_CLI_PATH=C:\Users\username\AppData\Local\agy\bin\agy.exe
TASK_EXECUTION_TIMEOUT_SECONDS=300
CONFIRMATION_TIMEOUT_SECONDS=120
# Опционально: прокси при сетевых ограничениях доступа к api.telegram.org
TELEGRAM_PROXY=http://127.0.0.1:1372
```

### 4. Запуск бота
Запуск осуществляется через зарегистрированную консольную точку входа:
```powershell
remote-control-bot
```
Либо через запуск модуля Python:
```powershell
python -m remote_control.controller.main
```

Для корректной остановки бота нажмите `Ctrl+C` (выполняется Graceful Shutdown с отменой фоновых сессий polling).
